Automatización y conciliación segura de procesos

¿Cómo saber qué solicitudes pueden procesarse y cuáles requieren intervención antes de tocar un sistema real? Este caso de estudio muestra un motor Python que compara CSV ficticios, aplica reglas explícitas y produce decisiones auditables en modo DRY RUN, sin llamadas externas.

Dos fuentes de evidencia separadas: mi experiencia profesional en WOM Chile (2022–2024) es contexto laboral declarado; este motor de ejemplo fue desarrollado con datos inventados para el portafolio. No reutiliza software, registros, datos ni procesos internos del empleador.

El problema

Antes de aplicar cambios en un proceso operativo hay que identificar solicitudes duplicadas, estados inválidos, registros desconocidos, aprobaciones pendientes y conflictos entre operaciones del mismo lote. Una automatización segura debe explicar por qué permite, bloquea u observa cada acción.

Decisiones de ingeniería

  • Reglas deterministas que emiten estado y motivo por cada fila.
  • Detección de duplicados por identificador y conflicto de operaciones sobre una misma cuenta.
  • Conciliación contra un catálogo ficticio antes de planificar una acción.
  • Auditoría en JSONL y resumen estructurado en JSON, además de un informe HTML.
  • Sin parámetro de ejecución real: solo se generan archivos locales de evidencia.

Reproducción en tu equipo

Solo necesitas Python 3.10 o superior, Git y los archivos públicos del proyecto. El CLI no necesita paquetes de terceros ni credenciales. Su salida funcional se guarda en evidence/; Python puede crear archivos de caché locales durante la ejecución.

git clone https://github.com/SebaGutierrezF/SebaGutierrezF.github.io.git
cd SebaGutierrezF.github.io/demos/process-automation
python -m unittest discover -s tests -v
python -m process_demo.cli --requests data/requests.csv --accounts data/accounts.csv --output evidence

Después, abre evidence/report.html en tu navegador y examina evidence/summary.json y evidence/audit.jsonl. Los 14 tests corresponden a una validación local registrada el 18-11-2026; este sitio no ejecuta los tests ni presenta un estado CI automático. Instrucciones completas en GitHub.

Qué demuestra y qué faltaría en un proyecto real

Demostrado: reglas de clasificación, validación de CSV, detección de repetidos/conflictos dentro del lote, pruebas locales y generación de motivos e informes.

Por desarrollar para un cliente: adaptar reglas y fuentes reales; autenticación, permisos, idempotencia persistente, integración con APIs o bases de datos, observabilidad y pruebas con datos autorizados. La demo no implementa esas conexiones.

La misma estructura podría servir como punto de partida para validar lotes operativos, preconciliar registros o preparar colas de revisión humana. Son posibles adaptaciones, no resultados demostrados en producción.
